# desktop-pet —— Electron 重写版

把 `../desktop-guide/`（PowerShell + WinForms）那套桌宠搬到 Electron。
**当前是骨架，不是成品** —— 见下面的"搬了多少"。

## 怎么跑

```bash
cd desktop-pet
npm install          # 会下载 Electron（约 100–200MB，只此一次）
npm start
```

> **国内网络**下从 GitHub 下 Electron 二进制会卡住（实测十几分钟不动）。用镜像：
> ```powershell
> $env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
> npm install
> ```

不想装 Electron 也能验路径逻辑（纯 node，7 项测试）：

```bash
npm test
```

### ⚠️ Electron 版本：**33 在这台机器上会崩，用 28**

2026-10-05 本机实测。先说结论：**Electron 33.4.11 起不来，28.3.3 正常**，所以
`package.json` 钉在 `^28`。这不是"这台机器跑不了 Electron"，只是版本问题。

排查过程（都留了可复现的探针）：

```
最小探针 tools/probe.cjs（只有 app.whenReady() 后打印一行再退出）

  electron 33.4.11 : [probe] module loaded … 然后 exit=-1073741819 (0xC0000005)
                     事件日志的"出错模块"就是 electron.exe 自己，偏移固定 0x1f1e1bb
                     --disable-gpu / --disable-gpu-compositing / --disable-features=Vulkan /
                     --use-angle=swiftshader 全试过，一样崩
  electron 28.3.3  : [probe] module loaded → [probe] app ready, quitting   exit=0  ✔
```

另外两条排查中被否掉的假设，记下来省得重走：

- **不是"未签名 exe 一律被拦"**。这台机器 Smart App Control 确实是强制开着
  （`HKLM\...\CI\Policy\VerifiedAndReputablePolicyState = 1`），但**本地用 csc 编译的、
  完全没签名的 WinForms exe 跑得好好的**（探针见仓库根的 `packaging-probe/`）。
  SAC 的证据不成立。
- **不是下载标记**：npm 解出来的 `dist/` 里一个 `Zone.Identifier` 都没有。

已知的坑还有一个：`--no-sandbox` 是必需的（不加，连 `--version` 都不返回）。

#### 想看渲染结果，别用桌面截图

桌面的 `CopyFromScreen`（BitBlt）**拍不到透明的置顶窗口** —— 实测窗口明明在 z=02、
Win32 枚举也报 `vis`，截图里却什么都没有，白白怀疑了一轮渲染。

要看渲染结果用这个（从渲染进程内部抓，最可信）：

```powershell
$env:PET_DEBUG_CAPTURE = "$PWD\debug-render.png"
npm run start:no-sandbox     # 窗口打开 1.5 秒后自动存图并退出
```

#### 派活链路：已通

```
node -e "import('./src/brain.mjs').then(m => m.askDsh('只回复两个字：可用', {}).then(r => console.log(JSON.stringify(r))))"
→ {"ok":true,"text":"可用","seconds":4.663}
```

用的是**你在 DSH 里已登录的账号**，不是环境变量里的 key —— 靠 `src/agents.mjs`
生成一份 `--patch` 把 `provider: deepseek-account` 注入进去，等价于 `dsh-agents.ps1` 的
`Write-AgentPatch`。

patch 的字段名是 desktop-guide 那侧踩出来的、写错不会报错只会静默不生效，
所以 `test/agents.test.mjs` 把它们锁住了：模型那条 id 必须是 `agent-default-model`；
权限那条必须是 `permission`（写成 `permission-presets` 会新增一条而不是覆盖，
权限就从来没生效过）。

## 交互

| 操作 | 效果 |
|---|---|
| 左键点宠物 | **弹性按压**：按下去压扁、松手弹回来（锚在底边中点，像按一个球） |
| 按住宠物 0.4 秒 | 说话：松开后识别，再判一次「这是要做事，还是只是跟你说话」——**聊天就地回，不起 agent** |
| 双击宠物 | 打开 **/ 收起** 打字派活输入条（同一个手势开关） |
| 朗读中点一下 | 打断朗读（不是再要一句） |
| 按住拖动 | 挪位置（位置记进 config.json） |
| 拖**图片**到宠物身上 | 直接给它看（内联图片，它真的能看到画面），说完结论照常念出来 |
| 拖其它文件/文字到宠物身上 | 填进"打字派活"输入条等你回车（**不直接开跑**，免得手滑就动了你的电脑） |
| 底部那排小按钮 | 问一句 / 对话 / 打字派活 / 框选监控区域 / 看它判过什么（见下） |
| 右键宠物 | 菜单：说一句、对话、打字派活、看它判过什么、框选/取消监控区域、我是醒着的、开机启动、暂停/继续、隐藏、设置、打开配置目录、退出 |
| **托盘图标**（右下角通知区） | 左键 = 显示/隐藏；右键 = 同一份菜单（对话、打字派活、框选、开机启动…） |
| **Ctrl+Alt+G** / **Ctrl+Alt+T** | 说一句 / 打字派活（和 PowerShell 版同一组热键；被别的软件占了就静默降级） |
| 输入条里回车 / 点发送 | 派活给 agent，跑完结论显示在气泡里 |
| 右键 → 看它判过什么 | 卡片：判断了几次、说了几次、沉默率、本地闸门省下多少次调用 |
| 气泡右上角的 × | 收起气泡（按 Esc 同效） |

### 底部那排小按钮

和 PowerShell 版**同一排、同一个顺序**，图标也是同一批码位（Windows 自带的图标字体，
零素材）。图标省地方，但图标不该让人猜 —— 悬停 0.1 秒就在上面浮一条深色提示写明它是干嘛的。

| 按钮 | 做什么 | "开着"的灯 |
|---|---|---|
| 问一句 | 让它现在看一眼并说一句 | 不亮（一次性动作） |
| 对话 | 开/收 **DSH 自己的 Web 界面**窗口 | 窗口开着就亮 |
| 打字派活 | 开/收那个输入条（和双击宠物同一条路） | 输入条开着就亮 |
| 框选监控区域 | 铺一层遮罩拖一个矩形（**右键这一格 = 取消框选**） | 框选过就亮 |
| 看它判过什么 | 把 `logs/decisions.jsonl` 画成一张卡片 | 不亮（一次性动作） |

灯的颜色是淡黄底 + 黄描边（和 PowerShell 版一样），一眼能看出"再点一下会发生什么"。

### 框选监控区域：只截那一块

整屏截图既费 token 又不私密。框选之后：

- 截图只留那一块，**按原生分辨率裁**（区域比 `screenshotMaxWidth` 还窄时就是原生的，不放大）
- **指纹也只算那一块** —— 区域外的动静不该叫醒模型
- 换区域的那一刻会**丢掉截图环**并重置指纹：环里的图是老区域拍的，交给模型等于让它看已经不该看的东西

落盘格式是 `region: { displayId, x, y, w, h }`，坐标是**相对那块屏左上角的 DIP**（不是绝对像素）——
缩放设置变了以后物理像素会失效，DIP 仍然指向同一个位置。换算链
（窗口 DIP → 屏幕 DIP → 物理像素 → 抓图缩放）在 `test/region.test.mjs` 里逐条钉住：
这种错**不会报错**，只会悄悄抓错一块。

想核对"到底截了哪块"，把裁出来的那张直接存下来看：

```powershell
node_modules\electron\dist\electron.exe --no-sandbox tools/region-probe.mjs
```

### 对话窗口 = DSH 自己的界面

不自己写聊天界面：Markdown、工具卡片、流式输出、审批按钮都得重画一遍，
而 DSH 发行包里本来就带这套（`dsh --profile web --port <口> --no-open`）。
点「对话」→ 桌面宠物左边的窗口里就是 DSH 的界面本身（PowerShell 版用 Edge 的 `--app=` 做同一件事）。

两个坑写进了 `src/webui.mjs`：`--patch` 必须排在 `--port` 前面（它是启动器的参数）；
服务打印的那条 URL 里带**一次性 token**，认的永远是它，不是拼一个裸地址。
服务由桌宠起、桌宠退出时收掉（你自己起的那个不动）。

### 开机启动

勾在右键菜单（和托盘菜单）里，写的是 `HKCU\...\CurrentVersion\Run` 的 `BloopPet` ——
**和 PowerShell 版同名**，两个版本切来切去不会留下两条都生效的记录。
不需要管理员权限，也能在"任务管理器 → 启动"里看见并关掉。写失败会明说原因（弹一条气泡），
不做静默失败 —— 静默失败的后果是"下次开机它没起来"，那时候人早忘了自己勾过这个框。

### 账本：余额 / 充值播报 / 今天花了多少 / 消费上限

口径和 `desktop-guide/ledger.ps1` **逐条对齐**（重写最怕的就是把口径悄悄改了）。余额来源只有两条：

| 来源 | 需要什么 | 说明 |
|---|---|---|
| **实时查余额** | 一个 DeepSeek API key | `GET https://api.deepseek.com/user/balance`，设置窗口里填 |
| **本地记账** | 无 | 每次查到的余额记进 `run/ledger.json`，于是"今天花了多少"和"是不是充值了"都算得出来 |
| 都没有 | — | 气泡页脚那一行**不占高度**，菜单点「账本…」明说缺什么 |

- **充值判据是"余额变大"**（默认 ≥ `rechargeMinDelta` 0.5 元）——比读任何别人的记账字段都直接。
  启动时先读一次做基线，所以重启不会把历史充值当成刚发生再播一遍。
- **今天花了多少 = 今天第一笔观测 − 最后一笔**（负数按 0：可能刚充值）。观测只在余额**变化**时落盘，
  只留最近 500 笔 —— 不为"今天花了多少"把文件撑大。
- **气泡页脚**一直显示 `余额 ¥75.69 · 上次调用 ¥0.12 · 今天 ¥3.20 / 上限 ¥50.00`；
  没配 key 时整行收起来。
- **每日消费上限**（默认 50 元，0 = 不设）：到线就**自动暂停**（不采样、不判断、不自动开口 = 不再花新钱）
  并在气泡上说明。"哪一天 + 哪个上限"是触发 key，所以跨天或者你把上限调大会**重新武装**
  （不然改成 100 之后它再也不管了）。暂停状态也落盘：到过上限之后重启，仍然是暂停。
- **上次调用花了多少** = 派活前后各读一次余额，取差值。注意文案写的是"上一次调用"而不是"这次" ——
  这期间你自己用 DSH 的消耗会一起算进来。

> key 的查找顺序：环境变量 `DEEPSEEK_API_KEY` → `desktop-pet/run/deepseek.key` →
> **`desktop-guide/run/openai.key`** ← 别漏了最后这条：PS 版 `advisor-openai.ps1` 的 baseUrl
> 就是 api.deepseek.com，那个文件里装的本来就是 DeepSeek 的 key，老用户不用为了账本再填一遍。

### 长期记忆：把观察日志压成一段，喂给判断

判断时能看到的只有最近 30 秒（截图 + 时间线），所以它原本不知道你上午在忙什么、
也不知道自己半小时前提醒过什么。日志其实一直有，缺的是"压缩 + 取用"：

```
logs/observe-YYYYMMDD.jsonl（窗口变化 + 每 2 分钟一条心跳）
   ↓ 确定性压缩，**不调模型**
【4小时内的活动（自动汇总，共 132 次采样）】
时间跨度：09:12 - 12:40　窗口切换 37 次
  · Code《main.mjs》 — 累计 1h20m，12 段
  · Chrome《知乎》 — 累计 24m3，5 段
注意：这段时间在两三个窗口之间来回切了 37 次（平均每 5.6 分钟一次）
```

这一段会接在判断提示词里"此刻的观察"后面（PowerShell 版是 advisor-core.ps1 同一处）。
**压缩不调模型**是刻意的：零 token、零延迟（~100ms）、重启也在（原料在盘上）、不引入新的不可靠环节。

| 参数 | 默认 | 说明 |
|---|---|---|
| `memoryEnabled` | true | 关掉就不压 |
| `memoryHours` | 4 | 往回看多久 |
| `memoryTop` | 5 | 记累计停留前几名 |
| `memoryMaxChars` | 700 | 记忆是提示词的一部分，太长会挤掉正文 |

右键菜单里两条：**「看它的记忆…」**（把那段话直接给你看 —— 不然"它凭什么这么判断"就是黑箱）、
**「清空记忆（从现在重新算）」**（只把起点推到此刻，不删日志）。

> 与 PS 版一处**有意的不同**：那边每 2 秒写一条观察日志（一天能到几 MB），
> 这边只在**窗口变化**时写，外加每 2 分钟一条心跳 —— 压缩只需要"换了没、待了多久"，
> 心跳负责给最后一个窗口封顶。旧日志留 7 天。

### 任务规则表：不同的应用不同的"多久看一眼、怎么看"

`config.json` 的 `taskRules` 是一张**声明式规则表**，顺序即优先级，进程名或窗口标题
**子串**命中（不分大小写）即算这一档（`src/profile.mjs`，口径照 PS 版的 `Get-TaskProfile`）：

```jsonc
{ "name": "卡牌/回合制游戏",
  "process": ["balatro", "hearthstone", "mtga"],
  "sampleSeconds": 0.6,      // 打牌要够及时
  "judgeMinSeconds": 20,
  "hint": "优先判断手牌能凑出的牌型…不要复述界面上已有的数字。" }
```

- 换档 = 换**采样节奏**：打牌 0.6 秒看一眼、看片 8 秒、桌面 10 秒；判断间隔也跟着这一档走
  （看片档 180 秒、桌面档 300 秒 —— 看片被打断的代价很高）。
  ⚠️ 判据是**采样率本身变没变**，不是"档名变没变"：同一条规则下的两个进程
  （balatro → hearthstone）档名一样，但节奏不能互相沿用（PS 版在这上面踩过）。
- `hint` 会**提前**写进判断提示词（"这一类任务优先看什么"），不是事后解释。
- 另有一张**学习表** `run/task-samples.json`（键 = 进程名小写）：只覆盖采样率，
  **不覆盖** hint 和 `judgeMinSeconds` —— 手写规则定"这类任务该怎么帮"，学习表定"多久看一眼"。
  学习值会被 `[minSampleSeconds, maxSampleSeconds]`（默认 0.3–60 秒）夹住。

设置窗口里能直接改这张表（JSON 文本框 + 实时校验：解析不了就**原样保留**，不会把好配置写坏）；
「看它判过什么」的卡片上也会显示**当前档** —— 不然"它怎么突然变勤快了"说不清。

自检：`PET_DEBUG_PROFILE=1` 会把几个典型场景（默认 / 打牌 / 看片 / 桌面）的档位算一遍打出来。

### DSH 问过来时，直接在球上点

DSH 的权限审批、`ask_user_question` 提问、计划评议会走 `pet-responder` 那套文件协议
（`run/ask/req-*.json` → 界面 → `ans-*.json`）。球上会弹出问题 + 可点的选项，
还能自己写一句。

三条语义是照 PowerShell 版抄的，写错会很难查：

- **「稍后」/倒计时走完 = 不写应答文件**，让 responder 自己超时后交给下一个应答者 ——
  不伪造一个假答案去糊弄模型
- **请求文件消失 = 对面已经超时或被别处答了** → 连按钮一起收掉（只收文字会留下还能点的按钮）
- **待回答时不许被别的气泡盖掉**（PowerShell 版踩过：进度播报每秒把问题文字盖掉）

> 要真用起来，`pet-responder` 得装进 desktop profile，且它的 `dir` 与这边的 `askDir`
> 指向同一个目录（默认都指 `desktop-guide/run/ask`）。

### 它派出去的活在干什么

后台子任务（DSH 的 `subagent` / 工作流）开跑时，气泡里会说一句
「它派出去的活还在跑：…（最久的已经跑了 N 秒）」，跑完收掉。

这条**不只是给人看的**：它同时塞进判断 payload 的 `agents` 字段 ——
否则主 agent 会把"屏幕很久没动"误读成"用户卡住了"，而真相常常是
"用户派了活出去，正在等它跑完"。

它说话时会**同时朗读**（用 Chromium 自带的音色，离线不需要额外装东西）。
朗读中点一下宠物 = 打断；系统句（`（…）`）、`SILENT`、「你在做：…」不会被念出来。

### 语音：先判"要不要真的去做"

语音识别出来的那句话**不是**直接派活的，中间多一道判定（`src/router.mjs`）：

```
按住说话 → 识别 → 判一次 ─┬─ TASK → 起后台 agent，跑完报结论
                          └─ CHAT → 就地回一句（气泡 + 朗读），**不起 agent**
```

判据交给已经热着的常驻会话，一轮 0.7–1.6 秒。**不用本地关键词表**，因为它分不清
「帮我把这个删掉」（任务）和「你把这个删掉了？」（对话）——中文里这俩只差一个助词。

判不出来时**按聊天处理**：宁可少起一个 agent，也不要在用户只是聊天时让后台 agent
开始动他的电脑。实测：

| 说的话 | 判定 |
|---|---|
| 你好呀，今天过得怎么样 | chat —「我很好呀…今天有什么想一起做的吗？」 |
| 刚才那个提醒挺好的 | chat —「有用就好～下次需要提醒随时说一声。」 |
| 帮我看一下现在几点了 | task → 派 agent |
| 把桌面那个临时文件删掉 | task → 派 agent（改写时它自己补了「先确认是哪个文件再删」） |

> **打字派活不参与这个判定**：那个框本来就写着"派活"，用户敲进去就是明确要做事。
> 只有语音这条"意图可能是任务、也可能只是说话"的路径需要分。
>
> 想连打字也判一次，把 `config.json` 里的 `routeTyped` 改成 `true`
> （**默认 false**）。打开后打字也走同一套分流：只是说话就地回一句、不动手。
> 代价是"确实要做的事"会多付一轮判定（不是白拿的）—— 而打字本来就是明确指令，
> 所以默认不判。

### 它自己什么时候开口

后台每 `sampleSeconds`（默认 2 秒）采样一次，但**每次采样不等于每次叫模型**：

```
每 2s：读前台窗口 + 算 8×8 画面指纹      （很便宜）
   ↓
本地闸门 src/gate.mjs（纯函数）
   画面变了吗？窗口换了吗？距上次多久？人还在不在？连着几次没说了？
   ↓ 值了才往下走
抓一张高质量截图 → 交给 DSH 主 agent 看一眼 → 说一句，或者回 SILENT
```

角标显示**累计"看过了但决定不说"的次数** —— 沉默是一等输出，不是"什么都没发生"。
判断过程都记在 `logs/decisions.jsonl`（`skip` / `silent` / `spoke` 三种）。

想只开窗口不开观察循环（调试用）：`$env:PET_NO_AUTO='1'`。

#### 待机（黑屏 / 锁屏 / 睡眠）与两条兜底

接的系统信号是 **锁屏 / 解锁 / 睡眠 / 唤醒**（`powerMonitor`）。进待机就停采样、停判断，
并把截图环丢掉——睡觉前那些图醒来只会害人（"画面静止 8 小时"这种数字项目里踩过一次）。

Electron **拿不到"显示器电源关掉"那个通知**（PowerShell 版是 `RegisterPowerSettingNotification` +
窗口消息，Electron 没有可挂的窗口过程），所以这里用两条真正管用的兜底代替：

| 兜底 | 判据 | 防的是什么 |
|---|---|---|
| 待机自愈探测 | 每 `standbyProbeSeconds`（30s）试一次：距上次键鼠输入 < `standbyProbeIdleSeconds`（60s）**且**抓得到屏 → 自己醒 | 系统通知漏发后它**永远**以为在待机，手里一张图都没有，等于哑了 |
| 连续抓不到屏 | `captureFailLimit`（3）次 → 进待机 | 远程会话断开 / 显示器切换时刷警告 + 拿旧图判断 |

还有一条与"看得见"直接相关：**截图太旧就当没有**（`shotStaleSeconds`，默认 30 秒）。
模型看不见图有多旧，给它一张过期的图，它会照着窗口标题**脑补**出一整套操作步骤——
看着专业，其实全是猜的。超过这个岁数的一张都不发，而且提示词里明说"看不到画面、
不要猜界面里有什么"，只允许说能确定的或者 SILENT。

自检：`PET_DEBUG_STANDBY=1` 会假装收到一次待机信号，再验它会不会自己发现"人回来了"。

鼠标**只在**宠物、气泡、输入条上被拦截，其余区域穿透到下面的窗口 ——
这是靠渲染进程实时报"指针在不在我身上"，主进程切 `setIgnoreMouseEvents`。

打字派活那条输入条有**三个**收起方式（原来只有一个，而且没人猜得到）：
再双击一次宠物、点条上的 `×`、按 **Esc**。

### 托盘图标：隐藏之后能叫回来，顺手能暂停

桌宠窗口是 `skipTaskbar`（不在任务栏占位），所以**没有托盘的话，"隐藏"等于再也找不回来** ——
只能重新启动一次。托盘补的就是这个洞：

| 动作 | 效果 |
|---|---|
| 左键点托盘 | 显示 / 隐藏桌宠（Windows 习惯） |
| 双击托盘 | 显示并置前 |
| 右键 → 暂停/继续 | **暂停 = 停掉观察循环**：不采样、不判断、不自动开口 |
| 右键 → 看它判过什么 / 打开配置目录 / 退出 | 和宠物右键菜单同一份实现 |

托盘图标用的是本项目自绘的 `assets/pet.png`（缩到 32×32），所以不引入任何第三方素材。
鼠标悬停能看到状态：`泡泡 · Bloop —— 在看着 / 已暂停（桌宠已隐藏）`。

### 用哪个模型 / 干活时给多大权限

右键菜单（和托盘菜单）里两条，候选项直接读 `agents.json`：

| 菜单 | 写进 config.json | 留空时 |
|---|---|---|
| 用哪个模型 | `mainAgentModel`（`agents.json` 里的名字，例如 `DeepSeek V4 Pro`） | `agents.json` 的 `mainAgent.model` |
| 干活时的权限 | `workAgentAccess`（例如 `只读` / `完全访问`） | `agents.json` 的 `workAgent.access` |

它们生成的是同一份 `--patch`（注进 `provider/model` 和 `permission.presets`），所以判断、派活、
对话窗口三条路用的是同一个选择。**换完会丢掉常驻会话**（它是按模型 + 权限 initialize 出来的）——
下一次调用才用新的，别以为"改了没生效"。

> 权限那一条会提醒你：选到 `完全访问`（`danger-full-access` + `approval: never`）意味着
> 它派出去的活**不再问你**。

### 它派出去的活：一张表（看记录 / 中断 / 派活）

右键或托盘菜单 →「它派出去的活…」。为什么做成窗口而不是菜单里再来几条：这本质是一张表
（状态 / 任务 / 开始时间 / 耗时 / 结论），子菜单只能点一下、看不到状态，也没法派活和中断。

```
状态      任务                        开始          耗时    结论
● 在跑    把桌面那个临时文件删掉…      10-13 15:20   12.3s   还在跑…
✓ 完成    试着跑一遍测试…              10-13 15:02   1m15s   测试全过了
✗ 失败    读一下那个日志…              10-13 14:58   6.0s    找不到那个文件
■ 已中断  把这段代码整理一下…          10-13 14:40   3.1s    用户中断
```

| 按钮 | 做什么 |
|---|---|
| 派活 | 和桌宠上那个输入框**同一条路**（不然两处行为会分叉） |
| 中断在跑的那条 | **停掉常驻会话**（一轮一个 prompt，停掉就等于中断这一轮），下次调用自动重建；走一次性调用时直接杀那个子进程 |
| — | 记录留最近 20 条，写 `run/tasks.json`，重启后还能看见上一轮的结论 |

> 桌宠启动时会**对账一次**：还挂着"在跑"的记录其实上一轮的残留（常驻会话已经不在了）——
> 会记成失败并写清为什么。不做这一步，表里会永远有一条在跑，看着像卡住了。

自检：`PET_DEBUG_AGENTS=1` 会把窗口开起来、塞两条假记录、再把页面里真正画出来的行读回来
（行数 / 状态标记 / 按钮可用性）。

**暂停的边界**（刻意划清，免得两头不讨好）：

- 暂停**只停它自己的主动性** —— 观察循环停下，不再自己找话。
- **手动要它说话仍然有效**（点它 / Ctrl+Alt+T 打字 / 语音），因为那是你主动要的，不是它多事。
- **DSH 的问答题仍然会弹**（`pet-responder` 那条线）—— 那是 agent 在等你回话，
  把它一起静音会让你以为 agent 卡住了。真要它彻底别出现，直接退出。

## 和 PowerShell 版的观感对齐（量出来的，不是估的）

重写最容易出的问题不是"功能少了"，而是"看着不像同一只"。所以下面这些尺寸都**对着
`desktop-guide/run/pet-preview-*.png`（PS 版自己渲染出来的预览）量过**：

| 项 | PS 版 | 这里 |
|---|---|---|
| 角色槽位 | 150×146 逻辑 px | 150×146 CSS px（`#pet`） |
| 窗口宽 | 320（角色居中、按钮条 220 居中） | 默认 `petWidth: 320` |
| 按钮 | 40×26，间距 5 | 40×26，间距 5 |
| 气泡内边距 | BubblePadX/Y = 13 | `padding: 12px 26px 12px 13px`（右边多留一截给 × ） |
| 字号 | `fontSize` 还要再乘一次 `uiScale`（那边 README 第 5 节） | 迁移时换算成 CSS px（`tools/migrate-config.mjs`，本机 6 → 16） |
| 空闲动作 | `bob = sin(tick/12)*3`（±3px 上下浮） | CSS `bob` 动画（±4px，2.4s） |

> 字号这一条最容易踩：把老配置的 `fontSize: 6` 原样抄过来，在这个 200% 缩放的屏幕上
> 就成了 6px 的蝇头小字（因为 PS 那边会再乘 `uiScale`）。迁移工具现在会向系统问 DPI、
> 换算一次并夹进 schema 的范围；换算完是个能看的字号。

想看自己的观感对不对，两条命令：

```powershell
$env:PET_DEBUG_CAPTURE = "$PWD\debug-render.png"   # 窗口渲染结果存图
npm run start:no-sandbox

$env:PET_DEBUG_TOOLBAR = '1'                       # 按钮条/按压/浮动/字号的自动自检
npm run start:no-sandbox
```

光晕颜色就是状态：`idle` 灰蓝 / `thinking` 琥珀 / `speaking` 蓝 / `silent` 灰。
角色图本身不变色 —— 图片改不了色，这是 PowerShell 版踩过的坑。

**沉默是一等输出**：模型回 `SILENT` 时不弹气泡，只把状态切成 silent。
