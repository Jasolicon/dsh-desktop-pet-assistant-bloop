# 泡泡 · Bloop

**一只趴在桌面上的鲸鱼。它看着你干活，大多数时候什么都不说。**

真该开口的那一次，它吐个泡泡说一句 —— 或者你按住它说话、打字、把文件丢给它，它就去把事情做了。

能陪你聊天、能在你干活时插一句、能看你打牌给个出牌顺序、也能把 docx / xlsx 真的改了 ——
但它的默认状态是安静。**能力都在，克制才是它的产品。**

---

## 它到底解决什么

用 AI 的人都会遇到同一件事：**你得先知道自己卡住了，还得有余力开口**。

可你在做菜、在修东西、在开会、在赶一个表格的时候，这两个前提经常同时不成立 ——
手占着、注意力占着，于是你既想不到要问，也腾不出手去问。

泡泡补的正是这一段：

| 常见的失效 | 泡泡的做法 |
|---|---|
| 来不及问（手被占着 / 正在通话） | 它自己看，你不用开口 |
| 不知道自己卡住了（同一件事试了三遍） | 它看着你试，试到第三次它说一句 |
| 每次都要重述背景 | 它记着今天看过什么，不用你重新交代 |

它一次只说一句。**大多数时候它什么都不说** —— 这不是没找到话说，是它判断过、决定不说。

## 它会说 / 它不会说

下面这些是它真说过、真沉默过的（来自它自己的判断日志）：

**它会说的：**

> 「两个桌宠叠一起时按钮会互相抢点击 —— 确认旧实例真的退出了没有。」
>
> 「鼠标悬停时倒计时要暂停，否则你正要点击的瞬间按钮就消失了。」
>
> 「同一个循环整理第三遍了，上面的判断可以合并。」

**它会闭嘴的**（连"理由"都会记下来）：

> *「任务正在正常跑、你在等它 —— 这属于正常等待，没有可证明的错误。」*
>
> *「你只是在阅读文档。」*
>
> *「屏幕上没什么异常，我也说不准在发生什么。」*

沉默不是"没有输出"，而是一次**判断的结果**。这是它和所有"随叫随到"的 AI 最大的区别。

## 怎么用

它在桌面上就是一只会眨眼的小宠物。**点一下**＝让它看一眼现在说句建议；**长按**＝你说话；
**打字**＝派活给它；**拖东西**到它身上＝当成任务交出去。

| 操作 | 效果 |
|---|---|
| 左键点它 | 现在看一眼，说句建议 |
| **长按它** | 你说话（松开就识别）—— 「帮我把那个 docx 第三段加粗」也行 |
| **Ctrl+Alt+T** | 打字派活（和说话走同一条管线） |
| 双击它 | 打断（停朗读；正在想也一起取消） |
| 拖文件 / 文字给它 | 交给它做 |
| 右键 | 对话 / 打字 / 语音 / 设置 / 账本 / 退出 |
| Ctrl+Alt+G | 同「点它一下」 |

**朗读**：它说的结论句会读出来（微软 Edge 神经音色，可换、可静音）。

**账本**：气泡最下方一行小字**一直**写着「余额 · 上次调用花了多少 · 今天花了多少」；
余额涨了（有人充值）它会说一声，每 30 分钟也会主动报一次。

**对话**：想长篇聊，右键「对话」直接开 DSH 自己的界面。

## 它能帮你做什么

下面这些都已经在你手上这台机器跑通，写法是「**你怎么操作 → 它实际做了什么**」，顺手把边界也写清楚。

### 对话：想长聊就聊

**你怎么操作**：右键 →「对话」。

**它做什么**：直接开 **DSH 自己的界面**（Edge `--app=` 模式，看着像原生窗口）—— Markdown、工具卡片、
流式输出、会话侧栏全都有，不是自绘的聊天框。要长篇讨论、要它自己翻文件动手，走这条。

**边界**：它开的就是桌宠主 agent 的会话。你如果在 DSH 界面里也打开了同一个会话，下一次自动判断
就会撞上"主会话被别处占着"，气泡会直说；想两边同时用，让对话窗口聊别的会话。

### 主动提示：你不开口，它也会说

**你怎么操作**：什么都不做。

**它做什么**：后台按任务档采样（看屏幕），**"值不值得问"由本地代码判**（画面变没变、窗口换没换、
你还在不在、距上次多久）；放行了才起一次模型，回一句话 —— 气泡说出来，同时念出来。

**边界**：一次只说一句。判得准不准，取决于它对"什么算异常"的理解，这是它唯一值得持续调的地方。

### 游戏里的实时建议（卡牌 / 回合制）

**你怎么操作**：打开游戏，什么都不用做。

**它做什么**：`config.json` 的任务档按**进程名或窗口标题**匹配（`balatro` / `slay` / `sts` /
`hearthstone` / `mtga` / `yugioh` …），命中就把采样压到 **0.6 秒一张**、最短 20 秒才可能再开口；
提示词里提前写死这类任务优先看什么：**当前手牌能凑出的牌型 / 连招、这一回合的出牌顺序、
资源（费用、血量、手牌数）的风险**，并且明确禁止它复述界面上已有的数字。

**边界**：全屏独占程序抓不到（GDI 截图的固有限制），多显示器只抓主屏。表里没有的游戏，
往 `taskRules` 加一行 —— 进程名、采样秒数、一句"这类任务优先看什么" —— 就享受同样待遇。

### 文档 / 表格 / PPT：真去改文件

**你怎么操作**：把文件拖到它身上，再说一句"把第三段加粗"；或者直接说话 / 打字派活：
「把 report.docx 第三段加粗」「把这个表格的月度汇总改成按周」。

**它做什么**：拖进来的文件走 DSH **原生 `@path` 引用**，模型自己调 `read` / `read_image` 去读
（实测拖一张 `.jpg` 进去，它调的就是 `read_image`，能把截图内容描述出来）。工作 agent 上挂着
`office-docx` / `office-pptx` / `office-xlsx` 三个 skill —— 创建、**局部编辑**、结构检查、
渲染成 PDF、声明交付物，都能做。跑完桌宠把最后一行结论报出来并念一遍（实测一句
「当前 CPU 占用率约为 29%」的任务 9.3 秒出结论）。

**边界**：它改的是**文件**，不是 WPS / Word 窗口里的内容 —— 它不替你在别人的窗口里点鼠标。
文件同时在你打开着的 WPS / Office 里时，自己留意是否提示"被占用 / 需要重新加载"。

### 让它自己装插件、自己查运行时

**你怎么操作**：说话或打字，「把 voice-input 插件挂上」。

**它做什么**：`plugin_manager` 本来就是 **DSH 给 agent 的工具**（八个 action：列已装 / 列可选 bundle /
开关插件 / 装 bundle …），我们只是照官方说明把默认关着的那一行打开 —— 和 DSH 是**同一套**，不是仿的。
另外挂了两个只读的 `cordis_inspect_*` 工具：写或调插件之前，先问清运行时里到底有什么 provider / 事件 / 配置 / 工具。

**边界**：能列"已装 / 可选"，**不能按关键词搜 npm** —— DSH 自己没把这层做成工具，要装就报
包名 / git 地址 / 本地路径。插件操作要求完全访问；把「工作 agent 权限」改成"工作区可写"，
每次操作就会在气泡上弹允许 / 拒绝按钮。

### DSH 要问你的时候，在气泡上答

**你怎么操作**：等气泡上出现按钮，点。

**它做什么**：headless 的 DSH 本来**没有应答者**（权限审批一律拒绝、`ask_user_question` 根本没挂）。
桌宠补上了这块：审批给「允许 / 拒绝 / 稍后」，提问直接用请求里带的选项标签。

**边界**：默认等 45 秒；超时或点「稍后」等于没答，**不会伪造一个答案糊弄模型**。

### 看它判过什么、看后台在干什么

**你怎么操作**：右键 →「看它判过什么」；或者它派活出去的时候看气泡。

**它做什么**：卡片刻着"它判过 12 次：说了 3 次，没说 9 次"和每一条沉默的理由；
后台 agent（包括它再开的子 agent）跑的时候，气泡每 3 秒刷一次它此刻在干什么（"改文件：xxx.docx"）。

**边界**：这份记录是它自己的日志，重启后还在。

## 装

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop-guide\DesktopGuide.ps1
```

| 需要 | 说明 |
|---|---|
| **PowerShell 7** | Windows 自带的是 5.1，脚本会明确提示你换 |
| **DeepSeek Harness** | 它把 DSH 的 agent 当"大脑"（用你已登录的账号，不用另配 key） |
| 语音输入（可选） | 首次使用按需下载 SenseVoice 模型，约 229MB，**本机离线识别** |

不需要 Docker、不需要 Node、不需要单独申请模型 key。

## 它不做什么

这一节是刻意的 —— 一个"随时在旁边"的东西，边界比功能更重要：

| 不做 | 为什么 |
|---|---|
| 不监听键盘输入 / 不读剪贴板 / 不记录窗口里的文字 | 侵入性太强，对判断帮助也有限 |
| 不抢焦点 | 它能点、能拖，但永远不激活、不打断你 |
| 不替你在别人的窗口里点鼠标、敲键盘 | 它的"操作"落在文件上（读、改、渲染、交付）；看屏幕可以，动手只在文件这一层 |
| 不把截图落盘 | 只在内存里留最近几张，落盘的只有窗口标题 / 进程 / 时间 |
| 不在你忙的时候插话 | 你一动手它就立刻让位；黑屏 / 锁屏 / 睡眠它直接待机 |
| 不写"什么时候该说"的死规则 | 该不该说由可测试的本地判据决定，说什么才交给模型 |

## 它是怎么做到的（给好奇的人）

一句话：**"要不要说"由本地代码判断，"说什么"才交给模型。**

模型在"什么时候该介入"这件事上通过率不到一半，所以门控必须是确定性的代码、而且可穷举单测；
模型只在放行之后，负责把那句话写好。这条分工是整个项目的地基。

具体到工程细节 —— 采样率跟着任务走（卡牌 0.6 秒 / 视频 8 秒）、采样即截图、用户操作优先级最高、
黑屏即待机、一个常驻运行时把每轮从 9 秒压到 1 秒、每次调用花了多少钱 ——
都写在 **[desktop-guide/README.md](desktop-guide/README.md)** 里，
包括每个决定当初为什么这么定、以及被实测推翻过什么。

产品层面的判断（为什么砍掉早期形态、方向与证据）在 **[随时指导项目_总纲.md](随时指导项目_总纲.md)**。

## 关于商业化

直说：**单独卖，很难。**

桌面宠物的历史是"装完炫两天然后删掉"，死因永远是同一个 —— 只有表达，没有判别。
消费者也不会为"帮判断"付钱；能卖的是"省时间"和"留痕"，而有实证表明这类效应是 modest 的。

它更可能的活法，是作为一个能力**嵌进你已经在付费的工作流**里（编辑器、通话软件、行业软件），
而不是独立产品。

但它真正值钱的东西不在代码里：是它一次次**"决定不说"**、以及你**因为它开口而改了做法**的记录。
这条数据攒起来之前，谈商业化都是空谈。
